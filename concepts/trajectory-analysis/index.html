Trajectory Analysis

Cell들을 발현의 연속적인 변화를 따라 늘어세워 상태 전이의 경로(trajectory)와 각 cell의 진행 정도(pseudotime)를 추정하는 분석.

#single-cell#trajectory#pseudotime

쉽게 말하면

사진 한 장(한 시점의 측정)으로도, 서로 다른 단계에 있는 cell들을 비슷한 것끼리 이어 붙이면 "분화(또는 활성화)가 어떤 순서로 진행되는가"를 재구성할 수 있습니다.

자세히

도구

단계 도구 로직 메모
뼈대 PAGA (Python) cluster 사이 연결성을 통계적으로 요약한 graph 전체 topology 파악. 개별 cell 위치는 안 줌
궤적, pseudotime Monocle 3 (R) UMAP 공간에서 principal graph(SimplePPT) 학습, root에서의 graph 거리 = pseudotime 대규모, 복잡한 branching. partition으로 무관한 계통 분리
Slingshot (R) cluster 중심을 잇는 곡선 구조가 단순할 때 안정적 (일반 지식)
운명 확률 CellRank 2 (Python) Markov chain transition matrix로 terminal state와 fate probability kernel 선택 가능 (pseudotime, velocity, RealTimeKernel 등)
조건 비교 condiments 조건 간 trajectory 차이 검정 (progressionTest 등) (일반 지식)

Monocle 3 단계

  1. preprocess_cds(num_dim = 30–50): 입력은 raw count 권장, 내부에서 정규화
  2. Batch 보정: align_cds(alignment_group = "batch") 또는 Harmony embedding 사용. 보정하지 않으면 batch가 pseudotime을 왜곡한다.
  3. reduce_dimension(): UMAP (tSNE는 국소 구조만 보존해 trajectory에 부적합)
  4. cluster_cells(): Leiden, partition
  5. learn_graph(): 핵심. noise가 많으면 스파게티처럼 나오므로 minimal_branch_len 등으로 주요 경로만 남김
  6. order_cells(): root 지정 (예: naive 상태, healthy control, baseline)
  7. Pseudotime을 따라 변하는 gene → module

PBMC 데이터의 근본 문제

  • 혈액 cell은 대부분 이미 분화가 끝난 상태로 순환한다. 골수 분화처럼 명확한 발달 연속체가 아니다.
  • 그래서 trajectory를 "분화"가 아니라 "기능적 상태 전이"(예: naive → activated → exhausted, 염증 단계)로 재해석하거나, trajectory 대신 cell proportion + DE로 같은 질문에 답하는 전략도 있다.
  • 결과가 생물학적으로 말이 되는지 반드시 검증한다.

실제 시간(시점)이 있는 데이터

  • 여러 시점(예: 0, 2, 4, 12주)은 한꺼번에 합쳐 하나의 공간에서 분석해야 시점 간 이동을 추적할 수 있다.
  • CellRank 2 RealTimeKernel: optimal transport(WOT)로 시점 사이 cell 이동과 시점 내 변화를 하나의 transition matrix로 계산 → 실제 시간 정보가 있을 때 가장 적합
  • Pseudotime vs 실제 시간 검증: 시점별 평균 pseudotime이 실제 시간 순서와 맞는지 확인 (예: 반응군에서 week 0 < 2 < 4 < 12)

그룹 비교 전략

질문 접근
환자 baseline이 정상과 비교해 어느 상태에 치우쳐 있나 함께 합쳐 학습, 정상을 root, 질병 cell의 분포 비교
치료 전 상태로 반응을 예측할 수 있나 fate probability가 그룹 간 다른지
시간에 따른 변화 RealTimeKernel, 시점별 pseudotime
반응군과 비반응군이 언제 갈라지나 branch 분석, 갈림길 근처 gene

모든 데이터를 무조건 합치는 것이 항상 좋지는 않다. 합치면 batch 차이가 극대화되고, 잘못된 상태 전이를 예측할 수 있다. 질문마다 합칠 범위를 정한다.
