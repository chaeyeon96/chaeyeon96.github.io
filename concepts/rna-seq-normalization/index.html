RNA-seq Normalization

Sequencing depth, transcript 길이, sample 구성, batch 같은 기술적 차이를 보정해 gene 발현을 비교 가능하게 만드는 과정. 비교하려는 대상(같은 sample 안 / sample 사이 / dataset 사이)에 따라 방법이 다르다.

#rna-seq#normalization#preprocessing

쉽게 말하면

같은 gene이라도 read를 많이 읽은 sample에서는 count가 크게 나오고, 긴 gene은 짧은 gene보다 read가 많이 붙습니다. Normalization은 이런 "측정 방식 때문에 생긴 차이"를 걷어 내는 일입니다.

자세히

1. Within sample: 한 sample 안의 gene끼리 비교

방법 보정하는 것 메모
CPM (counts per million) depth 길이는 보정 안 함. 같은 sample 안 gene 비교에는 부적합, sample 간 비교에는 dataset 수준 방법과 함께 쓴다
RPKM / FPKM depth + 길이 single-end / paired-end. Sample 간에 같은 발현도 다르게 보일 수 있어 sample 간 비교에 부적합
TPM depth + 길이 먼저 길이로 나눈 뒤 합이 100만이 되게 스케일. Sample마다 TPM 합이 같아 FPKM보다 sample 간 변동이 적다

2. Within a dataset: sample끼리 비교

RNA-seq은 절대량이 아니라 상대량을 잰다. 어떤 gene 몇 개가 엄청 많이 발현되면 나머지 gene의 비율이 상대적으로 줄어 보인다 (composition bias).

방법 원리
Quantile 모든 sample의 발현 분포를 똑같이 맞춘다. 분포 차이는 전부 기술적이라고 가정
Upper quartile 각 sample을 75번째 percentile 값으로 나눈다
TMM (edgeR) 극단값을 잘라 낸 log fold change의 가중 평균으로 scaling factor 계산 (일반 지식)
Median of ratios (DESeq2) gene별 기하평균 대비 비율의 중앙값으로 size factor 계산 (일반 지식)

3. Across datasets: batch correction

여러 연구나 시점의 데이터를 합치면 batch effect가 가장 큰 변동 원인이 되기도 한다.

  • Limma removeBatchEffect, ComBat: batch를 아는 경우. Empirical Bayes로 gene 간에 정보를 빌려 오므로 sample이 적어도 비교적 안정적이다.
  • 먼저 dataset 내 normalization으로 스케일을 맞춘 뒤에 batch correction을 한다.
  • Single-cell에서는 scVI, Harmony 같은 integration 방법을 주로 쓴다 → Batch Correction

Single-cell에서 흔한 선택 (일반 지식)

  • log1p(CPM 또는 counts per 10k): sc.pp.normalize_total → sc.pp.log1p. 가장 흔한 기본값
  • SCTransform: regularized negative binomial regression으로 depth 효과를 제거
  • Pearson residuals: 비슷한 아이디어의 분석적 버전
  • Pseudobulk DE에서는 raw count를 합친 뒤 TMM, DESeq2 방식을 쓴다 → Pseudobulk Analysis
