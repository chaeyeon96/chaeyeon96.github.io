1. Cohort and assays

Task · Participant, visit, biosample, model row를 서로 다른 단위로 관리한다.

Input → Output · 249명의 반복 방문과 biological specimens → modality별 sample × feature matrix, 12개 clinical outcome matrix, participant/visit metadata.

Intuition · 같은 사람에게서 해마다 검사지를 받으면 검사지는 늘지만 사람이 늘지는 않는다. Stool, plasma, PBMC는 같은 visit에서도 서로 다른 측정물이다.

2. Preprocessing and confounder adjustment

Task · Technical/environmental association을 고려하되 각 modality에 적용한 처리가 다름을 유지한다.

Input → Output · Raw assay matrices + metadata → feature-filtered 또는 residual-adjusted matrix.

Intuition · Feature가 disease 때문인지 age·diet·medication 때문인지 섞여 보이면, 분석 목적에 맞게 그 영향을 먼저 점검한다. 일부 modality에서는 feature를 제거하고 다른 modality에서는 값을 보정한다.

3. Longitudinal structure and validation

Task · In-cohort performance와 새로운 participant/cohort로의 generalization을 분리한다.

Input → Output · Participant-linked rows → training/CV, held-out, external evaluation partitions.

Intuition · 같은 사람의 첫 방문으로 배우고 다음 방문을 맞히는 시험과, 처음 보는 사람을 맞히는 시험은 난도가 다르다.

Details

  • 원문은 IQR/ICC, time·age·gender와 random effects를 포함한 GLM, repeated-measures correlation, SS-ANOVA로 temporal signal을 조사했다. 공통된 강한 시간 추세를 얻지 못해 각 time point를 독립 data point로 BioMapAI에 넣었다 (Methods pp. 17–18).
  • Model evaluation은 10% held-out을 먼저 제외하고 나머지에서 10-fold CV를 수행했다고 설명한다. Held-out은 같은 모집 cohort의 subset이며 external cohort와 다르다.
  • Methods는 donor ID를 기준으로 fold/held-out을 나눴는지 명시적으로 설명하지 않는다. 따라서 원문이 donor-separated validation을 보장했다고 쓰지 않는다.
  • 구현할 때는 participant 단위 partition을 먼저 정하고, filtering·confounder fitting·scaling·feature selection·hyperparameter tuning·ScoreLayer fitting을 training partition 안에서 수행하는지 확인한다 (일반 지식) → Cross-validation.
  • Time trend가 유의하지 않다는 것은 같은 사람의 biological/technical signature가 train/test 사이에서 공유되지 않는다는 증거가 아니다 (일반 지식).

4. Shared layers and outcome-specific heads

Task · 하나의 omics matrix로 여러 symptom outcome을 함께 예측한다.

Input → Output · X∈RN×pX\in\mathbb R^{N\times p}X∈RN×p → predicted outcome matrix Y^\widehat YY; ME/CFS에서는 clinical score 12개.

Intuition · 공통 교재를 공부하는 두 shared layer 다음에, pain·fatigue 등 각 과목을 맡는 작은 전용 branch가 붙는다.

Details

논문의 normalization 설명:

X′=(X−μtrain)/σtrain.X'=(X-\mu_{train})/\sigma_{train}. X′=(X−μtrain​)/σtrain​.

실제 구조는 BatchNormalization을 사용한다고 기술하며, training mini-batch의 통계와 moving average를 학습하고 inference에서는 training moving statistics를 사용한다. 아래 식은 dropout/BatchNormalization 연산을 생략한 구조 설명이다.

z1=ReLU⁡(W1x′+b1),dim⁡(z1)=64,z_1=\operatorname{ReLU}(W_1x'+b_1),\quad \dim(z_1)=64, z1​=ReLU(W1​x′+b1​),dim(z1​)=64,

z2=ReLU⁡(W2z1+b2),dim⁡(z2)=32,z_2=\operatorname{ReLU}(W_2z_1+b_2),\quad \dim(z_2)=32, z2​=ReLU(W2​z1​+b2​),dim(z2​)=32,

ht=ReLU⁡(W3,tz2+b3,t),dim⁡(ht)=8.h_t=\operatorname{ReLU}(W_{3,t}z_2+b_{3,t}),\quad \dim(h_t)=8. ht​=ReLU(W3,t​z2​+b3,t​),dim(ht​)=8.

여기서 ttt는 outcome, W,bW,bW,b는 학습 parameter다. 첫 두 hidden layer에는 50% dropout이 붙는다. 원문 Z3 식의 자기 참조 표기는 말미에서 따로 짚었다.

5. Loss functions and training

Task · Outcome별 적절한 loss를 사용하고 class imbalance·overfitting을 완화한다.

Input → Output · Training X,YX,YX,Y와 outcome type → trained symptom model.

Intuition · 정답이 yes/no인 문제와 점수를 예측하는 문제는 틀린 정도를 재는 자가 다르다. Shared representation은 여러 문제의 loss를 함께 받아 학습된다.

Details

Binary outcome의 standard negative log-likelihood는

LBCE=−1N∑i[yilog⁡y^i+(1−yi)log⁡(1−y^i)].\mathcal L_{BCE}=-\frac1N\sum_i[y_i\log\widehat y_i+(1-y_i)\log(1-\widehat y_i)]. LBCE​=−N1​i∑​[yi​logy​i​+(1−yi​)log(1−y​i​)].

Categorical outcome은

LCE=−1N∑i∑cyiclog⁡y^ic.\mathcal L_{CE}=-\frac1N\sum_i\sum_c y_{ic}\log\widehat y_{ic}. LCE​=−N1​i∑​c∑​yic​logy​ic​.

Continuous outcome의 Huber loss는 e=y−y^e=y-\widehat ye=y−y​일 때

Hδ(e)={12e2,∣e∣≤δ,δ∣e∣−12δ2,∣e∣>δ.H_\delta(e)=\begin{cases}\tfrac12e^2,&|e|\le\delta,\\\delta|e|-\tfrac12\delta^2,&|e|>\delta.\end{cases} Hδ​(e)={21​e2,δ∣e∣−21​δ2,​∣e∣≤δ,∣e∣>δ.​

위 BCE/CE는 부호가 정상인 standard definition이며 원문의 BCE 식에는 negative sign 누락 가능성이 있다. Huber의 δ\deltaδ는 논문 최종 hyperparameter 표에 명시되지 않는다. 공개 code는 tf.keras.losses.Huber()를 호출한다. Outcome에 서로 다른 특별 가중치를 주지 않았다는 Discussion에 맞춰 loss aggregation은 동일 중요도로 설명하되 실제 Keras output/loss type을 확인한다.

원문 regularization 표기:

Lreg=λ2∑kwk2.\mathcal L_{reg}=\frac{\lambda}{2}\sum_k w_k^2. Lreg​=2λ​k∑​wk2​.

6. ScoreLayer and evaluation

Task · Symptom reconstruction과 disease classification을 별도로 평가한다.

Input → Output · Trained omics-to-symptom model과 predicted Y^\widehat YY → auxiliary disease probability, regression/classification metrics.

Intuition · 첫 모델이 검사 결과로 12개 symptom 점수를 예측하고, 다음 작은 모델은 그 점수 조합으로 case/control을 구분한다.

Details

p^disease=σ(wTy^+b).\widehat p_{disease}=\sigma(w^T\widehat y+b). p​disease​=σ(wTy​+b).

ScoreLayer는 omics-to-symptom network와 구분되는 보조 classification layer다. 원문은 original clinical scores에서 초기 weight를 얻고 prediction accuracy에 따라 조정한다고 기술하며, 공개 code는 ScoreLayer와 선택적 WeightsAdjust를 제공한다. 전체 system을 disease label로 처음부터 end-to-end 학습했다고 바꿔 쓰지 않는다.

Symptom ttt의 reconstruction은

MSEt=1N∑i(yit−y^it)2MSE_t=\frac1N\sum_i(y_{it}-\widehat y_{it})^2 MSEt​=N1​i∑​(yit​−y​it​)2

로 평가한다. Figure 2C의 1−normalized MSE1-\mathrm{normalized\ MSE}1−normalized MSE는 AUROC도 R2R^2R2도 아니다. AUROC는 case가 control보다 높은 risk score를 받을 ranking 성능이며 accuracy와 다르다 → Confusion Matrix.

External cohort는 학습 feature 순서로 reindex한 뒤 없는 feature를 0으로 채웠다. 이때 0은 생물학적 부재의 실측값이 아니라 결측 대치값일 수 있다. Metabolome cohort의 coverage 약 79%/19%라는 본문 설명을 함께 읽는다. 외부 data에는 binary disease label만 있어 12개 symptom prediction을 직접 검증하지 못했다.

7. SHAP and biomarker categories

Task · Outcome별 모델이 어느 feature를 이용하는지 설명한다.

Input → Output · Shared layers와 outcome-specific head로 만든 submodel ftf_tft​, background/input matrix → symptom별 sample × feature SHAP matrix.

Intuition · 한 prediction을 baseline과 feature별 기여도의 합으로 나눈다. 같은 feature라도 다른 symptom이나 다른 사람에서는 contribution이 달라질 수 있다.

Details

원문은 outcome ttt마다 shared layers와 해당 head를 묶어 KernelExplainer(model_t.predict, X)를 적용했다고 설명한다. Tree SHAP을 쓴 것이 아니다 → Kernel SHAP.

ft(x)=E[ft(X)]+∑j=1pϕtj(x).f_t(x)=E[f_t(X)]+\sum_{j=1}^p\phi_{tj}(x). ft​(x)=E[ft​(X)]+j=1∑p​ϕtj​(x).

Feature set FFF에서 feature jjj의 Shapley value는

ϕtj(x)=∑S⊆F∖{j}∣S∣!(p−∣S∣−1)!p! [vt(S∪{j})−vt(S)].\phi_{tj}(x)=\sum_{S\subseteq F\setminus\{j\}} \frac{|S|!(p-|S|-1)!}{p!}\,[v_t(S\cup\{j\})-v_t(S)].ϕtj​(x)=S⊆F∖{j}∑​p!∣S∣!(p−∣S∣−1)!​[vt​(S∪{j})−vt​(S)].

vt(S)v_t(S)vt​(S)는 선택한 feature subset과 background distribution에 대한 model output이다. Kernel SHAP은 이 기여도를 근사한다; 모든 생물학적 feature를 실제 실험에서 제거한 효과가 아니다 (일반 지식).

  • Shared / disease-specific: 75% 이상의 output에서 top contributor로 반복되는 feature. Extended Data Fig. 3는 output별 top 30 feature를 살폈다고 설명한다.
  • Specific / symptom-specific: 일부 output에만 두드러진 contributor. 공통된 rank cutoff 외의 세부 선정 규칙은 전체 분석 code·Supplementary Tables 확인이 필요하다.
  • Sign: 이 연구는 score가 클수록 심하므로 positive SHAP은 더 높은 predicted severity에 기여한다. Feature concentration과의 Pearson/Spearman slope와 같은 quantity가 아니다.
  • Stability: Initialization/유사 architecture 반복에서 SHAP 안정성을 조사했으나, Figure 3와 Extended Data Fig. 4는 symptom biomarkers의 held-out 검증이 없었다고 명시한다.
  • Patterns: Monotonic, biphasic, dispersed는 관찰 pattern의 이름이다. 모든 feature에 polynomial regression을 실제 fitting했다는 뜻으로 쓰지 않는다.

Toy example · Baseline 0.25에 contribution +0.10,+0.04,−0.03+0.10,+0.04,-0.03+0.10,+0.04,−0.03을 더하면 prediction 0.36이다. 12개 output의 75%는 9개이므로, 이 기준을 그대로 적용하면 9개 이상 output에서 중요한 feature가 shared category에 들어간다. 손계산 예시는 위 loss/attribution 그림 오른쪽과 같다.

10. Cross-omics network comparison

Task · Healthy와 patient/subgroup 사이에서 module association이 어떻게 바뀌는지 비교하고 pathway-level hypothesis를 만든다.

Input → Output · Modality별 eigengenes, matched metadata와 symptom SHAP → baseline network, subgroup correlation differences, pathway summary.

Intuition · 팀 A와 팀 B가 평소 같이 움직였는데 patient에서 그 연결이 약해지거나 방향이 달라졌는지 살핀다. 같이 움직이는 관계와 A가 B를 일으키는 관계는 다르다.

Details

rab(g)=Spearman⁡(MEa,MEb∣group g),r_{ab}^{(g)}=\operatorname{Spearman}(ME_a,ME_b\mid\text{group }g), rab(g)​=Spearman(MEa​,MEb​∣group g),

Δrab=rabpatient subgroup−rabmatched healthy.\Delta r_{ab}=r_{ab}^{patient\ subgroup}-r_{ab}^{matched\ healthy}. Δrab​=rabpatient subgroup​−rabmatched healthy​.

위 conditioning 표기는 subgroup 안에서 계산한다는 설명이며, 원문이 특정 partial-correlation estimator를 사용했다고 주장하는 수식이 아니다. Confounder residualization과 subgroup comparison을 함께 고려한다.

  • igraph로 network를 분석했다. 원문은 ∣r∣|r|∣r∣ threshold 0.3으로 edge를 남기고 degree/betweenness centrality를 계산했다고 기술한다. Correlation cutoff와 adjusted-P significance cutoff는 별개다.
  • Patient subgroup는 female/male, age, weight, IBS/infection 등으로 나누고 해당 healthy counterpart와 비교했다. Figure 4B의 red/blue는 Δr\Delta rΔr의 증가/감소다. 양의 edge가 약해지면 Δr<0\Delta r<0Δr<0이어도 원래 correlation이 음수인 것은 아니다.
  • Figure 4 legend의 age 기준은 young <26, older >50이며, weight 기준은 BMI <26/>26이다. Figure 3의 demographic annotation <50/>50과 같은 기준으로 바꿔 쓰지 않는다. 정확히 26 또는 50인 participant의 처리 규칙은 추가 확인이 필요하다.
  • Pathway 분석은 microbial gene abundance의 short-/long-term/control 차이, immune/metabolite association, aggregated symptom SHAP을 결합한다. KEGG→metabolite→immune→symptom의 전 과정을 intervention으로 검증한 것은 아니다.
  • Group difference는 two-sided Wilcoxon rank-sum와 BH correction, correlation은 two-sided Spearman와 Holm–Bonferroni라고 Methods에 적혀 있다. Figure legend의 ‘FDR adjusted’와 일괄 동일시하지 않는다.
  • Correlation CI는 bootstrap 1,000회, 2.5/97.5 percentile로 제시했다. Bootstrap 단위가 participant인지 visit인지는 해당 서술만으로 확정하기 어렵다.

Toy example · Healthy r=0.5r=0.5r=0.5, patient r=−0.2r=-0.2r=−0.2이면 Δr=−0.7\Delta r=-0.7Δr=−0.7이다. Healthy r=0.5r=0.5r=0.5, patient r=0.2r=0.2r=0.2도 감소(−0.3-0.3−0.3)이지만 patient의 association은 여전히 양수다. 이 차이를 Figure 4A/B의 색 해석에서 구분한다.

Reproduction checklist

  1. 입력부터 확인: Row의 participant/visit key, 각 modality의 feature ID, 12개 score의 severity 방향을 확인한다.
  2. Partition을 고정: 새로운 사람 generalization이 목표면 participant-grouped split을 사용한다 (일반 지식). 원문의 visit-independent 접근과 비교해 별도로 보고한다.
  3. Training transformation을 저장: Feature list, confounder model, scaler와 class balancing 설정을 저장하고 test에 재사용한다.
  4. 실행 경로를 선택: 새 데이터 training은 BioMapAI_Training_Tutorial.ipynb, pretrained 추론은 Pretrained_DeepMECFS_Tutorial.ipynb를 시작점으로 삼는다.
  5. 논문 hyperparameter를 명시: Root class default에 의존하지 말고 Step 5의 최종 설정과 architecture 차이를 기록한다.
  6. 단계를 따로 검증: Symptom regression, ScoreLayer classification, external transport, SHAP stability, cross-omics correlation의 재현 결과를 나눠 기록한다.
  7. Source versions: 본 노트는 root code commit dd6ac30을 2026-11-03 확인한 기준이다. 현재 README의 notebook 이름 일부와 실제 root 파일명이 달라 위 링크는 실제 파일명으로 적었다.
